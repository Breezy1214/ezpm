**Create `tests/common/mod.rs`** with these shared helpers:

1. `pub fn ezpm_bin() -> PathBuf` — returns `PathBuf::from(env!("CARGO_BIN_EXE_ezpm"))`
2. `pub fn create_project() -> TempDir` — creates a realistic project skeleton in a TempDir:
   - `ezpm.toml` with `[project]` (name = "test-project"), `[paths]` (src = "src", darklua_build = "darklua_build"), `[aliases]` (Client = "src/client/", Server = "src/server/", Shared = "src/shared/", Packages = "Packages/")
   - `default.project.json` (minimal Rojo project: `{"name": "test-project", "tree": {"$className": "DataModel"}}`)
   - Directory structure: `src/client/`, `src/server/`, `src/shared/`, `Packages/`
   - `src/client/init.luau` containing `local util = require("src/shared/util")` (a require path that fix-requires can rewrite)
3. `pub fn run_ezpm(project_dir: &Path, args: &[&str]) -> Output` — spawns ezpm binary with `.current_dir(project_dir)`, sets `EZPM_NO_UPDATE_CHECK=1` env var, returns `Output`
4. `pub fn assert_success(output: &Output)` — asserts exit code 0; on failure prints stdout+stderr then panics
5. `pub fn assert_failure(output: &Output)` — asserts non-zero exit code; on failure prints stdout+stderr then panics

Use `tests/common/` directory (not `tests/helpers.rs`) so Cargo does not compile it as an independent test suite — this is the standard Rust Book Ch 11-03 pattern.

**Create `tests/fix_requires_test.rs`**:
- `mod common;` at the top
- Happy path: `fix_requires_rewrites_src_paths` — create_project(), run fix-requires, assert_success, verify `src/client/init.luau` was modified (file content changed from the original `require("src/shared/util")` to something containing an `@` alias path)
- Edge case: `fix_requires_exits_zero_when_already_fixed` — write a file with `require("@Shared/util")` already aliased, run fix-requires, assert_success
- Edge case: `fix_requires_exits_zero_on_empty_src` — create project but remove all .luau files from src/, run fix-requires, assert_success (nothing to fix)

**Create `tests/init_test.rs`**:
- `mod common;` at the top
- NOTE: `ezpm init` uses inquire interactive prompts. In a non-TTY environment (piped stdin), inquire will error. The test should verify the command does not panic/crash.
- Test: `init_exits_in_non_tty_environment` — create a bare TempDir (no ezpm.toml), run_ezpm with `&["init"]`, verify the process completes (does not hang) and returns some exit code (may be non-zero due to prompt failure — that is acceptable; the test verifies no crash/hang)
- Test: `init_without_project_dir_does_not_crash` — run init in an empty TempDir, verify it produces an Output (no panic)

**Create `tests/alias_test.rs`**:
- `mod common;` at the top
- Happy path: `alias_list_exits_zero` — create_project(), run `alias list`, assert_success
- Happy path: `alias_sync_exits_zero` — create_project(), run `alias sync`, assert_success, verify `.darklua.json` exists in project dir after sync
- Edge case: `alias_list_with_no_config_fails` — bare TempDir (no ezpm.toml), run `alias list`, assert_failure (config loading should fail)
- Edge case: `alias_sync_with_no_config_fails` — bare TempDir, run `alias sync`, assert_failure
- NOTE: Do NOT test `alias add` or `alias remove` as full integration tests — they use inquire interactive prompts (Pitfall 3 from RESEARCH.md). Only test non-interactive subcommands.

All assertions follow the locked decision: verify exit codes AND check that expected files exist/were modified — do NOT assert on specific stdout/stderr text.
